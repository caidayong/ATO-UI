# SRS 生成规则 v1

> **适用范围**：从迭代需求清单生成 `docs/prd/{V}/ATO_{V}-{一级需求}-需求规格说明书.md`。  
> **配套**：`prompt/prompt_prd_writer/需求规格说明书-生成提示词.md`、`.cursor/rules/srs-from-iteration-backlog.mdc`、`template/需求规格说明书-模版.md`。

---

## 1. 文档粒度

- **一份 SRS 仅一个一级需求**（模版附录 E）。
- 文件名：`ATO_{V}-{一级需求描述}-需求规格说明书.md`；`{一级需求描述}` 与清单「一级需求」列一致。

## 2. 需求类型分流

| 类型 | 前置 | 必读 | 不读 |
|------|------|------|------|
| **新增** | 页面 PRD **已验收** | 清单 + 页面 PRD + 源码 + requirements 检索 | — |
| **优化** | 进入 SRS 流程 | 清单 + 源码 + requirements 检索 | 页面 PRD、原始页面设计 |

## 3. 先图后文（Playwright）

- 清单 **`是否涉及UI=是`** → **必须先** `npm run srs:screenshots -- --version {V}`，**再**写 SRS 正文。
- 每 REQ **1～2 张** png；路径 **`assets/srs-screenshots/…`**（与 SRS 同目录，勿用 `../assets`）。
- `是否涉及UI=否` → **原型：** 写 **「无」**。
- Playwright 失败 → 不得定稿；写入 **# 待评审和澄清**。

## 4. 章节层级与清单对应

| Markdown | 清单列 |
|----------|--------|
| `## 1.1` | **一级需求** |
| `### 1.1.x` | **二级需求** |
| `#### 1.1.x.y` | **三级需求**（仅当列有内容） |

### 7.1 方案 1 — 三级为空时的 REQ 条文（**默认，P0**）

当某清单行同时满足：

1. **三级需求** 为 **— / 空**；  
2. 该 **二级需求** 在本一级需求下 **仅对应一条 REQ**；

则 **必须**：

- 使用 **`### 1.1.x {二级需求名}（REQ-xxx）`** 作为 **唯一** 功能节标题；  
- 将全部字段块（背景与动机、原型、需求描述…）写在 **该 `###` 下**；  
- **禁止** 新增 `#### 1.1.x.1` 或虚构三级标题；  
- **禁止** 用 `####` 仅作 REQ 容器。

**正例**：`### 1.1.4 缺陷详情（REQ-V1.0.1-P5-028）`（P5 范例）。

**反例**：`### 1.1.1 新建项目日报` + `#### 1.1.1.1 新建项目日报配置（REQ-010）`。

### 7.2 有三级需求时

同一 `###` 下按清单 **三级** 增加 `#### 1.1.x.y`；标题与三级列 **字面一致**。

### 7.3 页面聚合

多 REQ 合并同一 Tab 时，须在文首 **页面聚合** 写清 **§ ↔ REQ** 对照；**不得**对「三级为空、一 REQ 一行」增设虚构 `####`。

## 5. REQ 条文节必填字段

每个 **REQ 条文节**（`###` 或 `####`）须含：

背景与动机、用户场景、**需求类型**、优先级、输入/前置条件、**原型**、需求描述（**1. 正常流程 / 2. 异常场景 / 3. 限制条件**）、补充说明、验收标准。

- **需求类型** **唯一来源**：清单 **「需求类型」** 列（**新增** / **优化**）；须写在 **用户场景** 之后、**优先级** 之前，便于评审时识别存量优化与从 0 新增；同一 SRS 内若 REQ 类型混排，**禁止**仅在文首写文档级类型而正文省略。

- **背景与动机** **唯一来源**：清单 **「需求动机」**；`同 REQ-xxx：` 须展开冒号后正文。**禁止**粘贴「需求说明」、附录 A 差异、入口/Drawer。
- **异常场景** 标题不可删；无条目写 **「无」**。

## 6. 待评审和澄清

- 位于 **# 附录** 之前；Playwright 失败、P0 自检、冲突等 **只写本节**；阻断项标注 **P0** / **P1**（见验收清单 **§G**）。
- **禁止**单独产出 SRS 质量检测报告文件。

## 6.1 人工验收清单（双轨）

- 定稿前使用 **`docs/prd/SRS生成与验收清单.md`**（与提示词 §12 **【SRS 自检结果】** 配套，不可互代）。
- **L2 产品定稿**：§A～§H + §I；**# 待评审和澄清** 无 **P0**。
- **L3 spec-coding 就绪**：在 L2 通过后，§J 全部勾选，或按清单「L3 降级」登记外部真源并由研发签署。**L2 通过 ≠ L3 通过**。

## 7. 权威与裁决

- 迭代验收口径：**已定稿 SRS**。
- 冲突时默认以 SRS 为准并回写相关文档；禁止 **silent drift**。

---

**维护**：与提示词 §7～§12 同步；冲突时以 **黄金范例文首 + 附录 D + 提示词** 为优先解释。
