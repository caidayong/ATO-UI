# SRS 生成与验收清单

> 在 Cursor 按 **`prompt/prompt_prd_writer/需求规格说明书-生成提示词.md`**、**`docs/prd/SRS生成规则-v1.md`** 与 **`.cursor/rules/srs-from-iteration-backlog.mdc`** 生成 **`docs/prd/V*/ATO_V*-{一级需求}-需求规格说明书.md`** 后：  
> 1. **先** 完成对话内 **【依赖研读摘要】**、**【动机对齐表】**、Playwright 截图与 **【SRS 自检结果】**（提示词 §12）；  
> 2. **再** 按本清单 **双轨验收**（**L2** 产品定稿 → **L3** spec-coding 就绪，见下表）。

> **与页面 PRD 清单的关系**：`docs/prd/页面PRD生成与验收清单.md` 面向 **《页面需求与交互规格》**；本清单面向 **《需求规格说明书》（迭代 PRD / SRS）**。二者 **不可互相替代**。  
> **禁止** 单独产出 `SRS质量检测报告.md`；生成期问题只写入 SRS **# 待评审和澄清**（须标 **P0/P1**，见 **§G**）。

## 双轨门禁（方案 A）

| 轨道 | 含义 | 通过条件 | 主要使用者 |
|------|------|----------|------------|
| **L2 产品定稿** | 需求可说清、可写测试用例、可作迭代验收口径 | **§A～§H**（含 **§I**）全部勾选；**# 待评审和澄清** 无 **P0**；文首去掉「待评审草稿」；变更历史已追加定稿行 | 产品、测试 |
| **L3 spec-coding 就绪** | 工程师可 **以 SRS 为单一需求真源** 启动 AI spec-coding（需求分析→概要设计→详细设计） | **L2 已通过** + **§J** 全部勾选；或 **§J** 中允许的「外部真源」已在版本验收记录 **明示** | 研发（签署）、AI 实现 |

> **注意**：**L2 通过 ≠ L3 通过**。例如正文写「以实现组件为准」且未在 **§J.2** 登记外部真源时，**L2 可过、L3 不过**。  
> 合入 `docs/requirements/` 仍须 **单独指令**；**L3 通过** 不强制同步 `docs/spec/`，但建议在定稿后更新 **04-页面契约 / 02-数据模型**（见版本记录「定稿后动作」）。

## J. spec-coding 就绪（L3，研发签署）

> **前置**：**L2 已通过**。下列项保证工程师可基于 SRS 完成 **概要设计 + 详细设计** 并驱动 AI 编码；若单项不满足，须 **补写 SRS** 或走版本记录 **L3 降级** 并登记外部真源。

### J.1 实现映射（每个 REQ）

- [ ] 每个 REQ 条文节内或 **补充说明** 中可找到 **页面/组件路径**（如 `src/pages/…`、`src/components/…`），或 **优化类** 已说明「改动存量」的 **唯一挂载点**
- [ ] **跨 REQ / 跨 SRS** 依赖有 **引用表或对照表**（如 007/008/009 与附录 A；主从 REQ 不写进背景与动机）

### J.2 详细设计可落地（表单 / 列表 / 编辑类 REQ）

- [ ] 凡涉及 **表单、列表列、行内操作** 的 REQ：**需求描述** 中含 **字段级表格**（字段名、控件、必填、校验、数据来源），**或** 已在版本记录 **L3 降级表** 登记 **外部真源** 路径（如 `ProjectDailyReportEditor.tsx`、页面 PRD §x.x）
- [ ] 全文 **「以实现为准」/「以组件为准」** 类表述：已为 **每条** 登记降级 **或** 已在 SRS 补全字段/规则（**未登记则 L3 不通过**）

### J.3 状态与交互细则

- [ ] 存在 **多状态 UI**（生成中、删除门禁、Drawer 选步、预览/编辑切换等）的 REQ：有 **状态枚举表** 或 **状态机说明**（文字表 / Mermaid 均可），且与 **按钮 disabled / Tooltip** 一致

### J.4 数据与 Mock 契约

- [ ] SRS 涉及的 **持久化/Mock 函数**（如 `createDailyConfig`、`saveGeneratedDailyReport`）在 SRS **补充说明** 或 **附录** 中有 **入参/出参/错误语义** 表，**或** 显式写明 **类型真源** `src/types/…` + `src/mocks/…` 且版本记录 **@ 列表** 含该文件
- [ ] **生产 API** 未定义时：已标明 **P6 Mock only**；**禁止** SRS 虚构生产字段名而不标注 Mock

### J.5 AI spec-coding 任务包（版本验收记录或 SRS 文末）

- [ ] 已提供 **按 REQ 的 @ 文件清单**（最小集：本 SRS、清单、页面 PRD〔新增类〕、相关 `src/*`、`docs/spec/04` 对应 §）及 **禁止修改范围**（如「不得改 CaseDebugDetail 内部 Tab 顺序」）
- [ ] **L3 启动条件**：文首 **非**「待评审草稿」；**# 待评审和澄清** 无 **P0**

### J.6 逆向一致（P6 已实现 / 优化类推荐）
