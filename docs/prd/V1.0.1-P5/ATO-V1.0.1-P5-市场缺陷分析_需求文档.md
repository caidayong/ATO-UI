## 1. 范围与背景

建设从 **RDMS** 同步市场缺陷数据的能力，提供 **列表展示与个性化列**、**筛选与查询**、**行内编辑与详情弹窗**、**统计报表**与 **Excel 导出**，支撑质量分析与留档。

**非目标**：非市场缺陷域的通用工单系统；RDMS 产品本身功能改版。

---

## 2. 用户与场景

- 质量工程师每日查看增量缺陷、筛选团队/产品线、编辑归因字段。  
- 管理者进入报表页做月季统计。  
- 分析人员导出子集做线下复盘。

---

## 3. 功能需求（按二级需求聚合）

### 3.1 市场缺陷数据 RDMS 同步（REQ-022、023）

- **定时同步**：首次上线当季 **全量**；之后每日 **凌晨 1:00** **增量**同步及 **未关闭 Bug** 同步；字段与列表一致。同步源：RDMS 市场缺陷、测试 Bug（属性 beta-bug，创建部门为系统验证、工厂）。  
- **手动同步**：列表 **刷新** 触发小范围批量实时查询同步。

### 3.2 市场缺陷列表 — 默认列、列设置、过滤（REQ-024、025、026）

- **默认列**（与产品最终字段表对齐）：缺陷 ID、缺陷来源、创建日期、缺陷标题、缺陷类型、产品线、是否有效问题、缺陷实际归属团队、主要责任归属、主要责任人、流出原因、优化措施、优化责任人、计划完成时间，及自动化是否覆盖、是否可覆盖、不可覆盖原因、自动化未发现原因等；操作栏：**自动化复盘分析（图标）**、**刷新**。表头「缺陷类型」去重（与清单备注一致）。  
- **列设置**：支持显隐、顺序等（细则以 UI PRD 为准）。  
- **筛选**：产品线、是否有效问题、实际归属团队、主要责任归属。

### 3.3 市场缺陷编辑（REQ-027）

可编辑字段：是否有效问题、缺陷实际归属团队、主要责任归属、主要责任人、缺陷类型、流出原因、优化措施、优化责任人、计划完成时间、自动化是否覆盖、是否可覆盖、不可覆盖原因、自动化未发现原因。

### 3.4 缺陷详情（REQ-028）

点击 **缺陷 ID** → 经 RDMS 查询 → 弹框展示与 **RDMS Bug 详情页一致** 的信息结构。

### 3.5 缺陷信息查询（REQ-029）

基于列表数据查询，支持缺陷 ID 等条件（扩展项与 PRD 对齐）。

### 3.6 市场缺陷数据统计及报表展示（REQ-030）

列表上方 **「报表」** 进入统计页（参考 RDMS Bug 报表）。**数据范围**：**时间**与列表快照一致（只读）；**实际归属团队**、**是否有效问题** 可再选（默认「全部」，与快照覆盖规则见页面级 PRD **§3.4**）。**报表类型**（多选，顺序与展示顺序以工程常量为准，**2026-05-11** 验收）：总缺陷数、按是否有效、**按产品线**、**按实际归属团队**、按缺陷类型、按责任归属、按流出原因、**按是否自动化覆盖**（清单原文「按自动化已覆盖」）、按自动化未覆盖原因、按自动化未发现原因。详细交互、图型与版式见 **`ATO_V1.0.1-P5-页面需求与交互规格.md` §3.4**。

### 3.7 市场缺陷数据导出（REQ-031）

**导出** 弹框：文件类型（默认 **Excel**）、导出范围（全部或按时间、实际归属团队等）；文件编码默认 **UTF-8**。

## 5. 非功能与约束

- **外部依赖**：RDMS 可用性、鉴权、字段映射表。  
- **审计**：编辑、导出、同步建议留痕（推断，待安全基线确认）。

## 6. 异常与边界

| 场景 | 行为 |
|------|------|
| RDMS 超时/5xx | 可理解错误 + 重试 |
| 同步部分失败 | 合并策略以后端为准并提示（待确认） |
| 导出数据量过大 | 异步或分批 + 提示（待确认） |
