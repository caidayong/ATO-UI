## 1. 范围与背景

将市场缺陷分析 **任务化**：支持新建分析任务、列表管理、报告只读/编辑、**HTML 报告产出**、**DOC 导出**与 **邮件发送**，固化分析过程与结论并支撑对外汇报。

**非目标**：邮件服务器自建规范（沿用企业现有网关即可）。

---

## 2. 用户与场景

- 质量负责人按团队与时间范围创建分析报告任务，生成 HTML 供内网查阅。  
- 需修订结论时在详情页切换编辑态保存。  
- 对外汇报导出 DOC 并通过邮件推送协作方。

---

## 3. 功能需求（按二级需求）

### 3.1 新建缺陷分析报告（REQ-032，**2026-05-11 验收稿**）

- 入口：市场缺陷分析页 **Tab「分析报告」** 主按钮 **「创建缺陷分析报告」**（同结构 **编辑缺陷分析报告**）。  
- **表单字段（必填带 *）**：**报告名称***；**报告归属团队***（`mockTeams`）；**数据范围**（年 / 季度 / 月 / 实际归属团队，各 `Select`）；**RDMS 产品 ID***（多选至少一项）；**产品负责人 / 开发负责人 / 测试负责人***。  
- **不在创建/编辑弹窗勾选「报表类型」**：后台按常量 **`MARKET_DEFECT_ANALYSIS_REPORT_FIXED_TYPES`** 固定统计维度（与报表页枚举子集一致，含 **按自动化不可覆盖原因**）。  
- 确认后 **创建分析任务**（Mock）；报告 HTML 在详情页预览/编辑。

### 3.2 分析任务列表（REQ-033，**2026-05-11 验收稿**）

- **Tab 文案**：**「分析报告」**（`?tab=analysis`），与一级菜单「市场缺陷分析」整页名区分。  
- **工具条**：**报告归属团队** 下拉筛选（默认「全部」）；右侧灰色说明（进行中时重新生成/发邮件/删除不可用等）；**无**独立「任务名称」搜索框（以 `src` 为准）。  
- **列（左→右）**：报告名称（链至详情）；报告归属团队；创建人；创建时间；**有效缺陷总数**；**产品缺陷泄露率**；测试缺陷泄漏率；状态（进行中 / 已完成 / 异常）。  
- **操作列**：**仅图标 + Tooltip** — **编辑**（弹窗改任务元数据）、**重新生成**（进行中禁用；已完成/异常可点并将状态置进行中）、**发送邮件**（进行中/异常禁用；已完成可发）、**删除**（进行中禁用；其它二次确认）。**列表行不提供导出**。  

### 3.3 报告编辑（REQ-034，**2026-05-11 验收稿**）

- 点击 **报告名称** → 详情子路由 **默认只读预览**；详情顶栏 **编辑 / 保存** 切换 **HTML 报表块** 等可编辑区（与清单「右上角编辑」语义对齐，落位为 **Card `extra`**）。  
- Tab2 操作列 **编辑** 打开的是 **任务元数据弹窗**，**不等价**于详情页 HTML 编辑态。

### 3.4 报告导出（REQ-035，**2026-05-11 验收稿**）

- **导出 Word（`.doc`）** 仅在 **报告详情** 顶栏 **导出**；任务列表 **无**「报告导出」按钮（与清单原文差异见页面 PRD **§6**）。

### 3.5 报告邮件发送（REQ-036，**2026-05-11 验收稿**）

- 列表与详情共用 **`MarketDefectSendMailModal`**：**发件人** 只读；**收件人** 多选可搜索（`mockUsers`）；**团队选择** 单选（`mockTeams`）；**确认发送 / 取消**（Mock Toast）。

## 5. 非功能与约束

- **分析报告** 后台统计维度由 **`MARKET_DEFECT_ANALYSIS_REPORT_FIXED_TYPES`** 固定，与 **市场缺陷分析 · 报表**（`MARKET_DEFECT_REPORT_TYPE_OPTIONS`）子集对齐，避免双套口径。  
- **邮件**：抄送/密送规则、附件策略（若需要）待企业邮件规范。

---

## 6. 异常与边界

| 场景 | 行为 |
|------|------|
| 分析任务失败 / 异常 | **重新生成** 可重试（已完成或异常 → 置进行中）；状态机见页面 PRD §1.5 |
| 导出/邮件失败 | 明确错误 + 重试入口 |
| 并发编辑 | 冲突检测（推断，待确认） |
