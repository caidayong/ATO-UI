**空态**：
- 列表无数据时展示插画/提示 + 引导按钮（如"去创建"）

## 1 项目概况

### 1.1 基本信息

- **产品名称**：自动化测试平台（AutoTestOne，简称 ATO）
- **类型**：企业内部 Web 管理 / 测试平台（PC 端）
- **核心目标**：
  - 统一管理自动化测试用例、自动化应用与测试任务
  - 为版本回归提供一键执行能力和可视化测试报告
  - 提升测试效率与质量可视化程度，降低人工维护成本

### 1.2 主要用户

- 测试工程师：编写 / 调试 / 维护自动化用例
- 测试负责人 / 测试经理：规划测试计划、监控执行进度与质量
- 开发工程师：在提测或代码合入前，自行触发自动化回归

### 1.3 典型场景

- 在项目迭代周期内编写、维护接口 / UI 自动化用例
- 在版本发布前，为目标版本创建测试计划并一键执行自动化用例
- 发布后，通过报表查看各版本用例执行情况和质量趋势

## 2 数据流与状态机（供开发参考）

### 2.1 数据获取时机

| 页面 | 数据获取时机 | API 端点（Mock） |
|------|-------------|------------------|
| 项目管理 | 进入页面时 | GET /api/projects |
| 项目详情 | 进入页面时 | GET /api/projects/:id + GET /api/projects/:id/versions |
| 用例管理（新窗口） | 打开窗口时 | GET /api/versions/:id/cases |

### 2.2 全局状态（如需）

- **用户登录信息**：LocalStorage 存储，Context 透传
- **团队列表**：进入应用时获取，多页面共享（React Context）
- **环境列表**：全局固定（DEV/SIT/UAT/PRD），无需动态获取

### 2.3 页面级状态

**项目管理**：
```typescript
{
  filters: {
    team: string;      // 默认 "ALL"
    keyword: string;
  },
  // 当前实现：卡片列表为前端全量 Mock 筛选，无分页
  // 后续数据量增大时可增加 pagination
}
```

**项目详情**：
```typescript
{
  activeTab: 'versions' | 'info';  // 默认 'versions'
  selectedVersion?: string;        // 当前选中版本
}
```

### 2.4 关键状态机

**版本状态流转**：

```
未发布 ──[点击发布]──→ 已发布 ──[点击召回]──→ 已召回
   │                                          │
   └───────────[点击发布]───────────────────────┘
```

- **触发**：点击「发布」/「召回」按钮
- **API 调用**：POST /api/versions/:id/publish | POST /api/versions/:id/recall
- **UI 反馈**：
  1. 按钮 loading
  2. API 成功 → 刷新列表 → 按钮状态联动更新
  3. Toast.success

**技术实现提示**：
- Tab 切换：使用 AntD Tabs 组件，state 存储 activeKey
- 团队管理左右分栏：建议 Grid 布局（左侧 8:16 或 6:18）
- 用户多选弹窗：使用 AntD Select mode="multiple" + showSearch

**布局结构**：

```
面包屑：系统设置 / 基础数据
Tab：团队管理（默认）| 用户管理
```

**Tab 1：团队管理**（左右分栏）

| 区域 | 占比 | 内容 |
|------|------|------|
| 左侧 | 20% | 团队列表（新增/编辑/搜索/删除团队） |
| 右侧 | 80% | 成员列表（添加成员/搜索/列表/分页） |

- **左侧团队列表**：
  - 操作栏：添加团队按钮、搜索框
  - 列表项：团队名称、成员数
  - 操作：编辑、删除（**鼠标悬停时显示**）
  - 空态：引导添加团队

- **右侧成员列表**：
  - 依赖：需先选择左侧团队
  - 操作栏：添加成员按钮、搜索框
  - 表格列：工号、姓名、用户角色、邮箱、操作（删除）
  - 分页：是
  - 空态：引导添加成员

**关键交互**：
1. **添加团队**：Modal，字段：团队名称*（必填、唯一）
2. **编辑团队**：同添加弹窗，回显团队名称
3. **删除团队**：二次确认
   - 若团队有成员：`Modal.warning` 提示"删除团队请先移除团队下的项目数据！"
   - 若团队无成员：`Modal.confirm` 提示"此操作不可恢复，是否继续？"
4. **添加成员**：Modal，用户多选（支持搜索、多选）
5. **删除成员**：`Modal.confirm` 提示"确认删除{姓名}成员？"

**Tab 2：用户管理**（单列表）

- 操作栏：
  - 左上：同步按钮（点击后 loading → Toast 提示）
  - 右上：搜索框
- 表格列：工号、姓名、角色、邮箱、操作（编辑）

### 4.5 版本用例开发 / 用例管理（页面 5）

**基本信息**：
- 状态：🟢 已开发（第二阶段验收完成，持续小幅优化）
- 框架：新窗口
- 路由：`/version-dev/:projectId/:versionId/cases`
- 入口：项目详情页点击版本号（新开窗口）
- 入口参数：
  - 路径参数：`projectId`、`versionId`
  - 查询参数：`pn`（项目名称，可选）、`vn`（版本号，可选，用于左侧标题展示）

**技术实现提示**：
- 布局：Flex 分栏 + 拖拽分隔条，左侧默认窄栏（约 22%）可拖拽；左栏最小宽度需保证“搜索框 + 添加按钮”不挤压
- 目录树：使用 AntD Tree + 自定义 `titleRender`
- 用例详情 Tab：使用 AntD Tabs（`editable-card`），支持动态增减与多用例并行编辑
- 状态管理较复杂，建议：
  - 目录树数据：本地 state
  - 目录/用例启用状态：本地 map state
  - 当前选中用例：local state
  - 打开的用例 Tab：array state
- 删除类不可逆操作统一二次确认：优先 `Modal.confirm`，文案明确「删除后不可恢复」

**窗口恒定顶部**：


- 详情区域与步骤列表区域纵向铺满，不留底部空白

**接口请求步骤详情（核心）**
- URL 组装区：`协议 + 请求方式 + IP+端口 + 接口路径`
  - 协议：`默认/http/https`
  - `默认`值与当前环境默认协议联动展示
  - IP+端口默认取当前环境默认主机，环境切换时联动更新（不覆盖用户手改值）
- 子区块：`Params`、`Headers`、`Body`、`Cookies`、`变量提取`、`断言`
- `Params`：
  - Path 参数名不可编辑；内置 `server_ip/server_port`，其余从路径占位符（如 `{ip}`）解析
  - Path 必填规则：内置参数非必填，其余必填；“是否必填”不可编辑
  - “默认值”字段改为“参数值”；“说明”默认空；Path 区删除操作列
  - Query 参数改为“草稿行双击逐条新增”，不提供独立「添加」按钮
  - 参数值输入统一接入动态值输入能力（`DynamicValueInput`）
- `Headers`：
  - 交互对齐 Query（双击新增、行内编辑、删除）
  - 点击表格外/页面空白处退出编辑态
  - 参数值输入接入 `DynamicValueInput`
- `Body`：
  - 支持模式：`none`、`form-data`、`x-www-form-urlencoded`、`json`
  - `json`：输入区纵向铺满；“插入动态值”与“格式化”同一行
  - `json` 格式化：合法则标准化输出；非法则红框高亮并展示行列错误信息
  - `form-data` 中参数类型为 `file` 时，参数值切换文件树下拉；数据源复用文件管理数据
- `变量提取`、`断言`：
  - 均支持多行新增/编辑/删除
  - `断言` 区需有清晰表头（断言描述、提取来源、断言对象、断言逻辑、取反、预期结果）
  - 删除操作二次确认

**调用函数步骤详情**
- 子区块：`函数调用`、`变量提取`、`断言`
- 「选择函数」弹窗数据源复用“自定义函数”函数树
- `变量提取`、`断言`支持可交互编辑；`断言`区包含表头

**数据库操作步骤详情**
- 新增数据库操作步骤时，先弹配置弹窗：
  - 数据库类型：`MariaDb` / `ClickHouse`
  - 步骤名称：必填
- 详情区子页签：`SQL命令`、`变量提取`、`断言`
- `SQL命令` 支持多行输入；`变量提取`/`断言`支持增删改，删除二次确认

**等待步骤详情**
- 独立表单：`*等待时间 [数字输入] 秒`
- 支持整数输入，默认值为 1

**关键交互**：
1. **添加测试用例**：Modal，字段：用例名称、所属模块、标签
2. **添加子目录**：Modal，字段：目录名称、父级目录
3. **导出测试用例**：来自左侧「+」菜单（当前为 Mock 行为）
4. **启用/禁用切换**：
   - 树节点通过操作菜单切换
   - 列表“状态”列通过 Switch 单条切换
   - 列表顶部按钮支持批量启用/禁用
5. **步骤级删除/行删除**：统一二次确认，文案需强调不可恢复
6. **返回按钮**：关闭新窗口或返回项目详情（占位标注）

- Mock：`mockFunctionFiles`（`src/mocks/data.ts`）；与用例步骤 **调用函数 · 选择函数** 的 TreeSelect 数据源同源（见 `04-页面契约` §页面 5）

**技术实现提示**：
- 列表与编辑为**同页状态切换**（非独立子路由）；返回列表后保留表格筛选、勾选等 state
- 代码编辑：当前为 `Input.TextArea` + 等宽字体（后续可替换 Monaco 等）
- **运行**：前端 Mock，底部展示 stdout 占位文案；联调后替换为真实执行接口回写

**布局：列表态（单列表）**

- 容器：`Card`，内容区可滚动（与兄弟新窗口页密度对齐）
- **工具栏（单行）**：
  - **左**：添加函数、导入函数、删除（批量；无勾选时禁用）
  - **右**：`Input.Search`（实时过滤 **文件名 / 语言 / 作者**，不区分大小写）
- **表格**：
  - 列：文件名、语言（`Tag`，固定展示 **python**）、更新时间、作者、操作（**编辑** / **重命名** / **删除**）
  - **行选择**：`rowSelection`；**批量删除**：`Modal.confirm` 二次确认
  - **分页**：默认每页 8 条，`showSizeChanger`
  - **空态**：`Empty`

**布局：编辑态（Python 脚本）**

- 仍为 `Card`，与列表互斥展示
- **标题行（`title`）**：**「返回」按钮**置于 **「编辑函数：{文件名}」** 文案之前（同一行 `Space`）
- **右上角（`extra`）**：**运行**（默认按钮）→ **保存**（`type="primary"`）
- **说明文案**：「Python 文本编辑（Mock）…」灰色辅助说明
- **编辑区**：`Input.TextArea`，`autoSize`；打开「运行结果」区域后略减小高度，为底部输出腾出空间
- **保存**：将当前编辑内容写回该文件的 `content`，更新 `updatedAt`、作者（当前 Mock 为固定展示名）；`message.success`（Mock）
- **运行**：展开卡片**底部**「运行结果」区块（`pre`，浅灰底、等宽、可滚动）；内容为 **Mock**（含时间戳、文件名、stdout 占位说明、当前脚本行数、`exit code: 0` 等）；`message.success`；再次运行覆盖同一区域内容
- **返回**：退出编辑态，清空运行结果 state，回到列表（列表数据与搜索状态保留）

#### 弹窗与校验（列表态）

1. **添加函数**：Modal — 字段 **函数文件名称***；若未填扩展名则自动补全 **`.py`**；与已有文件名 **不区分大小写** 不可重复（`message.warning`）；确认后插入默认模板脚本（`def new_function(): ...`）
2. **导入函数**：Modal — `Upload.Dragger`，**多文件、可拖拽**；仅接受 **`.py`**；与已有文件名重复或非 `.py` 的项**跳过**并 `message.warning`；成功写入条数 `message.success`
3. **重命名**：Modal — 函数文件名称*；规则同添加（补全 `.py`、去重）
4. **单条删除**：`Popconfirm`「确认删除该函数文件？」

**进度规则**：
- 仅「运行中」任务进度每 10s 刷新（Mock 递增）

- 运行完成后是否清空下载目录：开关
- 执行范围：
  - 所属模块（双列选择：目录 + 模块多选）
  - 标签（多行条件）
- 并行配置：
  - 分组类型（按模块 / 按分组标签）
