## 1 全局约束（继承基线 + 本迭代补充）

### 1.1 强制页面清单（本迭代，页面名须与产品表述一致）

**主框架页面（在主框架内打开）**：

1. 产测软件管理 / 计划管理（计划列表）
2. 产测软件管理 / 计划管理 / 计划详情（Tab：**软件烧录表**、**操作日志**、**生产计划表**，从左至右）
3. 产测软件管理 / 计划管理 / 历史计划数据管理
4. 产测软件管理 / 履历表管理（仅 **履历表** 内容区，无第二 Tab）

**路由约定（占位，定稿后须同步 `docs/spec/01-信息架构与路由.md` 与 `src/constants/routes.ts`）**：

| 页面 | 建议路由 | 说明 |
|------|----------|------|
| 计划列表 | `/ptsw/plans` | 占位名 `ptsw` = production test software；支持 Query：`factory=CN/VN` |
| 计划详情 | `/ptsw/plans/:planId` | 入口参数：`planId`；支持 Query：`mode=changeEdit`、`factory=CN/VN` |
| 历史计划数据管理 | `/ptsw/plans/history` | 计划列表右上角入口；支持 Query：`factory=CN/VN`；**须注册于 `:planId` 之前** |
| 履历表管理 | `/ptsw/resume` | 单页表格维护 |

> **与 Spec 对齐**：当前 `docs/spec/01-信息架构与路由.md` 可能尚未收录上述路径，本 PRD 定稿后需增量更新 Spec，**禁止**静默假设路由已存在。

### 1.2 框架与布局

- **继承 V1.0.0 主框架**：顶栏 + 左侧主菜单 + 右侧内容区，PC 端 1440×900。
- **本迭代无新窗口**：不涉及新窗口顶栏与子菜单结构。

### 1.3 组件与视觉规范

- **继承 V1.0.0**：Ant Design；主色 #1677FF；成功/警告/失败色与基线一致。
- **列表页必须包含**：标题区（或面包屑）、主操作、筛选/搜索、数据区、分页（按需）、空态、加载态、无权限/只读态。

**时间格式**：与原始需求一致，日志与邮件相关展示可用 `YYYY-MM-DD HH:mm:ss`；列表日期列可与基线统一为 `YYYY-MM-DD HH:mm`（在《差异与取舍》说明）。

### 1.4 状态枚举与颜色映射（本迭代新增）

| 枚举类型 | 状态值 | Tag 颜色 | 说明 |
|----------|--------|----------|------|
| **计划状态** | 匹配中 | 蓝（processing） | 生成/匹配处理中 |
| | 匹配失败 | 红（error） | 匹配失败，支持重新匹配；详情不展示烧录表 |
| | 匹配异常 | 火山色（volcano） | BOM 异常行整行标红；有烧录表预览但**禁止提交** |
| | 待确认 | 橙（warning） | 可编辑、可提交 |
| | 已提交 | 绿（success） | **不可再编辑列表「编辑」**；仅只读查看（须提供「查看」类入口，见 4.1） |

### 1.5 通用交互规范

- **继承 V1.0.0**：表单校验、Toast、空态、危险操作二次确认文案 **「此操作不可恢复，是否继续？」**
- **导出**：导出中按钮/全局 loading；失败 Toast + 支持重试。
- **搜索框**：支持回车触发；筛选默认「全部」。
- **BOM 查询失败**：接口层自动 **重试 3 次**；仍失败则阻断创建/刷新并展示可读错误（占位 API 错误信息）。

### 1.6 权限与审计（DFX）

- **编辑类操作**（新建计划、列表编辑、详情保存/提交、变更提交、履历增删改、批量替换、**历史计划数据行编辑**）：仅 **生产测试** 团队相关成员 + **管理员**。
- **查看**：可按角色放宽只读。
- **操作日志**：创建、编辑、提交、变更、删除、导出、邮件结果等须留痕（详情页「操作日志」Tab 展示；后端为准）。

### 1.7 外部依赖（占位 API）

- 工厂生产系统 **物料 BOM 查询接口**（只读）：新建/重传生产计划 Excel 后，用于生成「软件烧录表」行数据。
- **邮件发送**：提交/变更审批通过后的通知（收件人：手动输入 + 按团队批量选择）。
- **审批流**：计划 **变更提交** 后进入审批，**生产测试组 PL** 审批；**审批通过后自动发邮件**。
- **历史计划数据（NFR）**：在线保留 **≥10 年**（REQ-040）；**异地定期备份**（REQ-041，与履历表备份同级）；详见 4.4 与 `ATO-V1.0.1-P4-计划管理-新增.md` §2.12。

## 2 数据流与状态机（本迭代）

### 2.1 数据获取时机（Mock 边界）

| 页面/场景 | 数据获取时机 | API 端点（Mock 占位） | 说明 |
|-----------|-------------|----------------------|------|
| 计划列表 | 进入页面 | `GET /api/ptsw/plans` | 筛选、分页 |
| 计划详情 | 进入页面 | `GET /api/ptsw/plans/:planId` | 含三 Tab 数据源或分接口加载 |
| 软件烧录表行 | 生成/刷新 | `POST /api/ptsw/plans/:planId/regenerate`（示例） | 内部调 BOM，失败重试 3 次 |
| 提交计划 | 点击提交 | `POST /api/ptsw/plans/:planId/submit` | 含校验、邮件任务 |
| 变更提交 | 点击提交变更 | `POST /api/ptsw/plans/:planId/change-requests` | 进入审批；通过后发邮 |
| 履历表列表 | 进入页面 | `GET /api/ptsw/resume` | 查询、分页 |
| 履历批量替换 | 用户确认 | `POST /api/ptsw/resume/batch-replace`（示例） | 按查询条件或勾选行 |
| 历史计划数据列表 | 进入页面 | `GET /api/ptsw/plans/history`（示例） | 工厂 Tab、年份/周次筛选、关键词查询、分页 |
| 历史计划数据编辑 | 行编辑保存 | `PATCH /api/ptsw/plans/history/:rowId`（示例） | 可改程序名称、checksum、存放路径 |
| 历史计划数据导出 | 导出确认 | `POST /api/ptsw/plans/history/export`（示例） | 按年+多周范围导出 Excel |
| 历史计划可选年份 | 进入页面/打开筛选 | `GET /api/ptsw/plans/history/years`（示例） | 返回近十年或库表 DISTINCT year |

> 以上为**契约占位**，真实路径以后端/Spec 为准；前端不得虚构已存在的生产接口。

### 2.2 页面级状态建议

**计划列表**：

```typescript
{
  filters: { week: string; status: 'ALL' | 'matching' | 'failed' | 'abnormal' | 'pending' | 'submitted'; keyword: string };
  factory: 'CN' | 'VN';
  pagination: { current: number; pageSize: number };
}
```

**计划详情**：

```typescript
{
  planId: string;
  activeTab: 'burn' | 'log' | 'production'; // 对应 UI：软件烧录表、操作日志、生产计划表
  mode: 'normal' | 'changeEdit'; // 变更流程进入时为 changeEdit
}
```

**履历表管理**：

```typescript
{
  filters: { keyword: string /* 可扩展多字段 */ };
  selectedRowKeys: string[];
  batchReplaceModalOpen: boolean;
}
```

**历史计划数据管理**：

```typescript
{
  factory: 'CN' | 'VN';
  filterYear: number;        // 默认当年；可选近十年
  filterWeek: string;        // 格式 W16；非必填；默认上一周
  keyword: string;
  pagination: { current: number; pageSize: number };
}
```

### 2.3 关键状态机

**计划生命周期（简化）**：

```
匹配中 ──[解析/BOM 成功]──→ 待确认 ──[提交成功]──→ 已提交
   │                          │
   └──[失败]──→ 匹配失败 ──[重新匹配]──→ 匹配中
                              │
                              └──[存在 BOM 异常行]──→ 匹配异常（禁止提交，可重新匹配）
                              └──[校验失败]──→ 保持待确认 + 明细提示
```

**计划变更（非独立页）**：

```
列表点「变更」──→ 直接跳转详情 Tab「软件烧录表」编辑态
──→ 填变更详情 ──→ 提交变更 ──→ **待 PL 审批** ──→ 通过 ──→ 自动邮件 + 变更次数+1
```

## 4 页面详细设计

### 4.1 产测软件管理 / 计划管理（计划列表）— P4-1

**基本信息**：

- **状态**：🟢 已验收（2026-04-27）
- **框架**：主框架
- **路由**：`/ptsw/plans`（占位）
- **入口参数**：无

**技术实现提示**：

- 表格：`Table` + `Tag` 展示计划状态；工具条 `Space` + `Select` + `Input.Search` + `Button`
- 新建计划：`Modal` + `Upload.Dragger`（或 Upload）上传 Excel
- 变更：直接进入变更编辑态 `navigate(/ptsw/plans/${id}?mode=changeEdit)`

**布局结构**：

```
面包屑：产测软件管理 / 计划管理
工具条：周次筛选 | 计划状态筛选 | 搜索框（回车） | [查询] | [历史计划数据管理]     [新建计划]（左）
顶部切换：工厂 Tab（国内工厂 / 越南工厂，默认国内工厂）
数据区：表格 + 分页
```

**表格列**：

| 列名 | 说明 |
|------|------|
| ID | 计划标识 |
| 计划名称 | 创建计划时填写 |
| 周次 | 如 2026-W16 |
| 状态 | 匹配中 / 匹配失败 / 匹配异常 / 待确认 / 已提交 |
| 变更次数 | 数字 |
| 创建日期 | |
| 提交日期 | 未提交可 `-` |
| 变更日期 | 无变更可 `-` |
| 创建人 | |
| 操作 | 见下 |

**操作列**：

- **编辑**：仅 **未提交**（匹配中/匹配失败/待确认）展示或高亮；**已提交**隐藏或置灰并 Tooltip 说明「已提交不可编辑」。用于修正**新建计划时的输入**（如 Excel 传错）：进入可重传流程（见关键交互）。
- **变更**：已提交计划是否允许变更——**允许**（走变更审批流）；若产品规定仅「已提交」可点「变更」，则在《待评审》注明。
- **删除**：二次确认；**已提交计划不允许删除**（隐藏或禁用）。

**关键交互**：

1. **新建计划**：Modal — 输入计划名称并上传本地「生产计划」Excel（模板字段见 4.2 Tab3 / 示例数据）；校验格式与必填列；点击确认后计划创建成功并 Toast，列表新增一条「匹配中」状态记录；后端异步生成软件烧录表并在完成后回写计划状态（如更新为待确认），BOM 失败按接口策略重试 3 次。
2. **编辑（修正输入）**：进入 **计划编辑/详情** 流程：须支持在详情或前置步骤 **重新上传** Excel 并 **重新生成软件烧录表**（与原始需求一致）。
3. **变更**：点击后直接跳转 **计划详情**，`activeTab=软件烧录表`，编辑态，`mode=changeEdit`；不再单独选择「软件更新/软件下架」类型（变更语义由编辑烧录表行内容承载，见 REQ-V1.0.1-P4-035）。
4. **删除**：`Modal.confirm`，文案「此操作不可恢复，是否继续？」；已提交不可删。
5. **进入详情**：点击列表中的 **计划名称** 进入计划详情页；已提交计划在详情页以只读为主（不允许再编辑计划输入）。
6. **工厂隔离**：顶部 Tab 支持 `国内工厂/越南工厂` 数据隔离管理；切换后列表仅展示当前工厂数据，且进入详情与返回列表需保持工厂上下文（Query：`factory`）。
7. **历史计划数据管理**：工具栏 **右上角**「历史计划数据管理」按钮 → 跳转 `/ptsw/plans/history?factory=CN|VN`（见 4.4）。

**空态**：无计划时引导「新建计划」。

**无权限**：隐藏新建/编辑/提交/变更/删除，或统一提示「无编辑权限」。

### 4.2 产测软件管理 / 计划管理 / 计划详情 — P4-2

**基本信息**：

- **状态**：🟢 已验收（2026-04-27）
- **框架**：主框架
- **路由**：`/ptsw/plans/:planId`
- **入口参数**：`planId`（来源：计划列表）；Query 可选：`mode=changeEdit`

**技术实现提示**：

- `Tabs` 三页签顺序固定：**软件烧录表** → **操作日志** → **生产计划表**
- 软件烧录表：`Table`，可编辑单元格可用 `Form` 包裹行或 Drawer 行编辑（实现选型由前端定）
- 变更对照：可用左右 `Col` 双表或「原表只读 + 下方编辑表」；MVP 可用单表 + 高亮变更行（占位）
- 操作日志：`Timeline` 或只读 `Table`

**布局结构**：

```
面包屑：产测软件管理 / 计划管理 / 计划详情
顶栏操作：[保存] [提交] [返回]  （无编辑权限时隐藏/禁用提交）
Tab1 软件烧录表：工具条（搜索、导出、提交）+ 表格
Tab2 操作日志：只读时间线/表格
Tab3 生产计划表：工具条（搜索、导出）+ 表格（解析自上传 Excel，列与模板一致）
```

**Tab1 — 软件烧录表（字段锁定，REQ-V1.0.1-P4-035 优化后）**：

| 字段 | 说明 |
|------|------|
| 生产任务单编号 | |
| 物料代码 | |
| 物料名称 | 原「物料描述」 |
| 数量 | |
| IC料号 | |
| IC型号 | |
| 程序名称 | 原「软件名称」；可编辑输入框 |
| checksum值 | 原「软件状态」列位；**字符串**；可编辑输入框，**双击单元格**进入编辑 |
| 是否烧录 | 枚举：是 / 否（程序名称为空时置空） |
| 软件存放路径 | **新增末列**；只读；Mock 示例 `\\192.168.1.30\firmware\ASH\V262B107` |

- 表格样式参考产品提供的「板卡软件烧录表」示意图（图1，图片路径：`C:/Users/caijinpeng/.cursor/projects/e-AI-project-AutoTestOneUI/assets/c__Users_caijinpeng_AppData_Roaming_Cursor_User_workspaceStorage_9c0dbb509e1387b851fee19e6d4a4c65_images_image-1f0e91b9-074b-4ca1-9fd5-6b38d0d85d12.png`）。
- 支持一对多结构：**一个物料代码可对应多条 IC 明细行**（IC料号、IC型号、程序名称等）；表格前置公共列（生产任务单编号、物料代码、物料名称、数量）可按组 **`rowSpan` 合并**展示。
- **IC 数据口径**：**IC料号 → IC型号** 一一对应；**IC型号 → IC料号** 可一对多。
- 规则1：当「程序名称」为空时，「checksum值 / 是否烧录」须置空显示。
- 规则2（已移除）：原「软件状态=已下架」红色高亮规则随 REQ-V1.0.1-P4-035 删除「软件状态」列而取消。
- **履历表匹配 UI 标记（REQ-036）**：程序名称列 — `updated` **橙色**（含空→有、旧→新）；`not_found` 且程序名称为空 **红色**；红色空值**阻断提交**。
- **BOM 异常行（REQ-037）**：`bomMatchFailed=true` 时 **整行背景标红**；计划状态为 **匹配异常** 时禁止提交；**匹配失败** 时不展示烧录表。
- **提交前校验**：若存在「要烧录但无程序名称」的行，或存在红色标记且程序名称为空的行，**阻断提交**并列出明细。
- **提交邮件（REQ-038）**：提交弹窗须预览邮件正文，**列出所有橙/红标记板卡明细**（含旧→新场景的 `previousProgramName`）。

**Tab2 — 操作日志**：

- 只读；字段建议：时间、操作人、动作类型、摘要、结果（以后端为准）。

**Tab3 — 生产计划表**：

- 数据来源于上传的「板卡周生产计划」Excel；导出为 Excel（模板字段固定）：
  - **周次**
  - **生产任务单编号**
  - **物料代码**
  - **名称**
  - **数量**

**关键交互**：

1. **保存**：保存当前 Tab 可编辑内容（含烧录表行编辑）；Toast 反馈；写日志。
2. **提交**：校验通过后状态 → 已提交；触发邮件；收件人：**手动输入 + 按团队批量选择**（提交弹窗或侧栏配置，占位）。
   - 提交弹窗新增配置项：`是否带Excel附件`（单选，默认 `是`；可选 `否`）。
   - 选择 `否` 时，仅发送邮件正文，不导出 Excel 附件发送。
3. **变更流程内**：展示 **变更详情** 区（变更原因、影响范围、备注）；**提交变更** → 创建审批单 → **PL 审批通过** → 自动邮件（附件 + 变更详情正文）；失败可 **重发邮件**（占位）。
   - 变更原因：下拉选项（默认「迭代更新」「bug修复」）+ 下拉内「添加」按钮支持自定义新增并保存；
   - 布局：备注位于第二行，影响范围占据首行主要输入宽度；
   - 变更高亮：变更编辑态下，被修改过的明细行需底色高亮，便于识别修改范围。
4. **搜索**：Tab1、Tab3 支持关键词搜索（回车）。
5. **导出**：Tab1、Tab3 支持导出；写日志。
6. **权限**：只读用户不展示「提交」「保存」或禁用。
7. **提交联系人复用**：首次提交填写发送人/抄送后，后续该计划变更提交弹窗默认回填上次信息，允许继续编辑后提交。
8. **状态分流**：`匹配失败` — Tab1 空态无烧录表；`匹配异常` — 展示烧录表但禁用提交；`待确认` — 可提交。

**基本信息**：

**技术实现提示**：

- 页面壳：`ListPageShell` + 工厂 Tab + `FilterToolbar` 右置筛选
- 表格：`Table` + 前置列 `onCell` **`rowSpan`** 合并；IC 及软件列不合并
- 行编辑 / 导出：`FormModal`（`maskClosable={false}`）

**布局结构**：

```
面包屑：产测软件管理 / 计划管理 / 历史计划数据管理
顶栏：[返回计划列表] + 辅助说明（默认当年上一周）

```

**表格列**：

| 列名 | 合并 | 说明 |
|------|------|------|
| 计划日期 | 是 | 同任务单+物料组合并 |
| 周次 | 是 | 同上 |
| 生产任务单编号 | 是 | 分组键之一 |
| 物料代码 | 是 | 分组键之一 |
| 物料名称 | 是 | 分组键之一 |
| 数量 | 是 | 同上 |
| IC料号 | 否 | 一对多 IC 明细 |
| IC型号 | 否 | **同 IC料号必同 IC型号** |
| 程序名称 | 否 | |
| checksum值 | 否 | |
| 是否烧录 | 否 | |
| 软件存放路径 | 否 | |
| 操作 | 否 | 行编辑 |

**行合并规则**：连续行满足 **生产任务单编号 + 物料代码 + 物料名称** 相同时，合并 **计划日期、周次、任务单、物料代码、物料名称、数量** 六列；合并范围以**当前页**数据为界（分页切换后重新计算）。

**筛选与默认**：

| 控件 | 规则 |
|------|------|
| 年份 | 下拉，默认 **当年**；可选 **近十年**（对接后由库表 DISTINCT year 返回） |
| 周次 | 下拉 `Wxx`，**非必填**；默认 **上一周**；清空后展示所选年全部周次 |
| 关键词 | 匹配生产任务单编号、物料代码、IC料号、IC型号 |

**关键交互**：

1. **返回计划列表**：保留 `factory` Query，回到 4.1。
2. **行编辑**：Modal 可改 **程序名称、checksum值、软件存放路径**；其余只读。
3. **导出 Excel**：Modal 选择 **年份 + 多周次**；支持批量导出（Mock 成功 Toast）。
4. **工厂 Tab 切换**：重置为当年 + 该工厂默认上一周。

**非功能性（后台）**：

- **REQ-040**：历史数据在线保留 **≥10 年**。
- **REQ-041**：**异地定期备份**，与履历表备份（REQ-019）同级。

**空态**：当前工厂/筛选条件下无数据时 `Empty` 引导。

**无权限**：无编辑权限时隐藏行编辑或禁用保存（与 DFX 一致）。

## 7 相对原始需求的差异与取舍

| 项目 | 原始需求/清单 | 本 PRD 处理 | 原因 |
|------|----------------|-------------|------|
| 时间格式 | 示例中有 `HH:mm:ss` | 列表可用 `HH:mm`，日志/邮件可用秒级 | 与 V1.0.0 基线表格习惯对齐，避免重复争议 |
| 变更 UI 布局 | 原文「原计划只读 + 变更后可编辑表」 | 允许 MVP 用单表 + 变更标记或双表并列 | 实现可行性，不改业务含义 |
| 变更类型选择 | 原先列表先弹窗选「软件更新/软件下架」 | 改为直接进入变更编辑态；以「软件状态」字段承载更新/下架语义 | 减少一步操作，避免重复决策 |
| 软件烧录表列（REQ-035） | 原：物料描述、软件名称、软件状态（枚举下拉）、烧录阶段 | 优化为：物料名称、程序名称、checksum值（字符串输入框，双击编辑）、软件存放路径；删除烧录阶段与「已下架」高亮 | 用户试用反馈，与生产/履历口径对齐 |
| 履历展示粒度 | 原示例偏“每条 IC 一行” | 调整为“一个板卡一行”，同板卡多组 IC 在列内分行展示 | 贴合业务阅读习惯，序号/操作更清晰 |
| 履历批量替换范围 | 原需求可泛化为多字段替换 | 本期收敛为“软件版本专项替换（含Checksum值/路径联动）” | 降低误替换风险，满足高频维护场景 |
| 路由路径 | 原始需求未写 | 使用 `/ptsw/...` 占位 | 待 Spec 统一命名 |
| 需求 ID 覆盖 | 原文写 REQ-001~019 | 以当前 `docs/prd/V1.0.1-P4/迭代需求清单.md` 为准（含 REQ-035~041） | 清单已演进 |
| 历史计划数据管理 | 原迭代未含 | 新增 P4-4 独立子页（REQ-039）；列表入口在计划列表右上角 | 第二步历史烧录匹配源线上化 |
| 历史数据 NFR | 原迭代未含 | REQ-040 十年存储 + REQ-041 异地备份 | 与履历表 DFX 对齐 |
| 计划状态 | 原 PRD 四态 | 增加 **匹配异常**（REQ-037） | BOM 异常与匹配失败区分 |
| 烧录表 UI 标记 | 原 PRD 未写 | 橙/红程序名称标记 + 邮件正文清单（REQ-036/038） | 履历表第三步可视化 |
| IC 料号/型号 | 未明确 | **同 IC料号必同 IC型号**；同型号可多料号 | 业务数据一致性 |
| 历史列表行合并 | 未明确 | 任务单+物料维度 rowSpan，IC 列不合并 | 与详情烧录表阅读一致 |
| 「变更」可操作状态 | 未明确是否仅已提交可变更 | PRD 倾向 **已提交后走变更审批**；未提交走编辑/提交 | 逻辑分层，待产品确认 |
