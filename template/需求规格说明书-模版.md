# 文档说明

> **文档类型**：需求规格说明书（SRS），即本仓库流程中的 **迭代级 PRD（交付研发与测试）**。经 **产品经理审核定稿** 后，供 **研发**（方案与实现）、**测试**（验收、用例与回归口径）、**AI**（spec-coding / 辅助实现）使用。  
> **交付物文件名**：`ATO_V{X.Y.Z}-{一级需求描述}-需求规格说明书.md`。`{一级需求描述}` 与迭代需求清单「一级需求」列一致；文件名非法字符（如 `\ / : * ? " < > |`）替换为 `_`。黄金范例见 `template/ATO_*-需求规格说明书-范例-*.md`（含 `-范例-` 后缀；正式稿不含）。

> **《页面需求与交互规格》的定位**（路径：`docs/prd/V{X.Y.Z}/ATO_V{X.Y.Z}-页面需求与交互规格.md`）：用于 **HTML 页面原型 / 线框落地**（布局、控件、§ 章节锚点）；**不是**迭代产品的唯一真源。可与本正文 **§ / REQ** 交叉对照；**研发、测试与实现验收口径以本 SRS 为准**。

> **本文档的定位**：承载 **单个一级需求** 的完整条文（见 **附录 E**）；章节结构、编号层级与写法深度参照黄金范例 **`template/ATO_V1.0.1-P5-需求规格说明书-范例-市场缺陷分析.md`**。**文档粒度（必读）**：**一份 SRS 仅覆盖迭代清单中的一个一级需求**；同一迭代多个一级需求须拆成多份文件。详见 **附录 E**。

**章节引用约定**：正文中的 `## 1.1`、`§1.1.x` **仅在本文档内有效**；跨文档沟通请使用 **文件名 + REQ-ID** 或 **文件名 + §**（示例：`ATO_V{X.Y.Z}-{一级需求描述}-需求规格说明书.md` + **REQ-xxx**），避免口头简称「看 1.1」在多份 SRS 并存时混淆。

**编号约定**（正文 `##` / `###` / `####` 与清单列对应）：

- `## 1.1` — 对应迭代清单 **一级需求**（本文件仅承载 **一个** 一级需求，见附录 E）
- `### 1.1.x` — 对应迭代清单 **二级需求**（能力簇或子模块）
- `#### 1.1.x.y` — **仅当**清单 **三级需求** 列有内容时；与三级 **字面一致**。**禁止**为挂 REQ 而虚构四级标题（见 **§7.1 方案 1**）

**页面聚合（可选）**：若同一 `###`（二级）下有多条 **有三级** 的 REQ，用多个 `####`；若清单 **三级为空** 且 **一二级对应一条 REQ**，条文（含原型）**全部**写在 `### 1.1.x 二级名（REQ-xxx）` 下，**不设** `####`。

**需求描述结构（固定小节，勿删节）**：各功能点须依次包含 **`• **原型：**`**（在 **需求描述** 之前）、**`• **需求描述：**`** 下 **`1. 正常流程` → `2. 异常场景` → `3. 限制条件`**；REQ 元字段须含 **`• **需求类型：**`**（用户场景之后、优先级之前）。无异常条目时 **保留 `2. 异常场景` 标题**，正文写 **「无」**。详见 **`docs/prd/SRS生成规则-v1.md`**。

**验收基线**（版本通配）

- **迭代级权威（研发 / 测试 / AI）**：**当前迭代已定稿的本 SRS**。业务口径、验收勾选项、与 REQ-ID 对应的条文 **以实现与测试对本 SRS 为准**。
- **REQ 覆盖（完整性）**：本稿所对应 **一级需求** 在迭代清单中的 **全部 REQ**，须在本 SRS 内有 **可定位条文**，或 **显式说明**（不适用、推迟至某迭代、合并至其他 REQ 等）并 **可追溯**；定稿前禁止清单内 REQ 无交代。
- **需求类型分流**（见 **`docs/prd/SRS生成规则-v1.md`**）：
  - **新增**：编写前须 **页面 PRD 已验收**；编写时 **须对照** `ATO_V{X.Y.Z}-页面需求与交互规格.md`。
  - **优化**：**不读** 页面 PRD、原始页面设计；以 **清单 + 源码 + 截图 manifest** 为准。
- **原型截图**：清单 `是否涉及UI=是` → 每个 **REQ 条文节**（`###` 或 `####`，见 §7.1）在 **需求描述** 前须有 **原型：**（嵌入 png，1～2 张/REQ）；`=否` → 写 **「无」**。先 Playwright 后正文。
- **裁决规则**：当 **页面交互规格**、**原型截图**、**原型代码**、**迭代清单** 与本 SRS **冲突**时：**默认以已定稿的需求规格说明书（迭代 PRD）为准**，并 **回写**相关文档或升版 SRS（按变更流程）；若团队临时决议以原型为准，须在 SRS 或变更记录中 **显式记载**。
- **外部系统 / 接口边界**：以前端 **可观测行为** 与本文业务口径为准；**数据源字段语义、同步与过滤口径、接口契约** 以 **接口文档、数据字典或后台权威定义** 为准。若本 SRS 与后台可实现性冲突，按变更流程 **修订 SRS 或调整接口**；**禁止**在实现中 **silent drift**。

**文档生成依据 — 新增类**（需求类型=新增）

1. **迭代需求清单**：`docs/prd/V{X.Y.Z}/ATO_V{X.Y.Z}-需求清单.md`  
2. **页面需求与交互规格（已验收）**：`docs/prd/V{X.Y.Z}/ATO_V{X.Y.Z}-页面需求与交互规格.md`  
3. **Playwright 产出**：`docs/prd/V{X.Y.Z}/assets/srs-screenshots/manifest.json`（UI=是 的 REQ）  
4. **源码核对**：`src/pages/`、`src/components/`、`src/types/`、`src/mocks/` 等  
5. **`docs/requirements/`**：已检索（命中路径或 NOT FOUND）

**文档生成依据 — 优化类**（需求类型=优化）

2. **页面 PRD / 原始页面设计**：**不适用**（本类型不读）  
3. **Playwright 产出**：同上  
4. **源码核对**：同上  
5. **`docs/requirements/`**：已检索（命中路径或 NOT FOUND）

### E.1 一份 SRS 仅允许对应一个一级需求

- **严格要求**：**一份**需求规格说明书（迭代 PRD）**只能覆盖迭代需求清单中的某一个一级需求**，及其下属的二级、三级需求。**禁止**在同一份 SRS 正文中并列承载 **多个不同一级需求** 的产品条文。
- **迭代内多个一级需求**：须 **拆成多份 SRS 文件**，每份独立命名、独立定稿；文件名中 `{一级需求描述}` 与该份文档唯一对应的一级需求一致（与清单「一级需求」列对齐；非法路径字符替换为 `_`）。
- **本稿**：`## 1.1 [一级需求名称]` 仅描述 **唯一** 一级需求；REQ 范围仅涵盖该一级需求在清单中的条目。

### E.2 与全量需求库拆分的衔接

- 合入 `docs/requirements/` 时仍遵循 `.cursor/rules/requirements-module-split.mdc` 等业务域规则；**SRS 按一级需求拆分** 与 **全量库按业务域归档** 的对应关系，以评审通过的映射为准。
